# 逐次一貫性（Sequential Consistency）の解説

出典: M. Herlihy and J. Wing, "Linearizability: A Correctness Condition for Concurrent Objects", ACM TOPLAS, 1990, 3.3章（pp.472-473）および2章の定義。

## 1. 定義

逐次一貫性は、Lamportが提案した並行オブジェクトの正しさの条件である。論文では次のように述べられている。

> 履歴が正当な逐次履歴と等価であることを要求する。

この文に出てくる語は、2章で次のように定義されている。

| 用語 | 意味 |
|---|---|
| 等価（equivalent） | すべてのプロセスPについて H\|P = H'\|P が成り立つ。各プロセスが見る自分の操作列が同じなら、プロセスをまたいだ全体の並びは違ってよい |
| 逐次履歴 | 操作が重ならず、1つずつ順番に実行された履歴 |
| 正当（legal） | 逐次履歴が、オブジェクトの逐次仕様に合っている（キューなら先に入れた要素が先に出る） |

つまり逐次一貫性は、次の2つを満たす並べ方が存在することを要求する。

- (a) 各プロセス内の操作の順序を保つ
- (b) 並べた結果が、オブジェクトの仕様に合う

## 2. linearizabilityとの違い

linearizabilityは、次の2条件を要求する。

- L1: complete(H') が、ある正当な逐次履歴Sと等価である
- L2: 実時間の先行順序 <H が、Sでも保たれる（<H ⊆ <S）

逐次一貫性は、L1に相当する条件だけを要求し、L2は要求しない。そのため、実時間で先に終わった操作を、並べ直すときに後ろへ回してよい。論文が「逐次一貫性はlinearizabilityより弱い」と言うのはこのためである。

「先行順序」には2種類あり、混同しやすい。

| 種類 | 逐次一貫性での扱い |
|---|---|
| 実時間の先行順序（操作Aの応答が操作Bの呼び出しより前） | 要求しない |
| 並べ直した逐次履歴Sの中での順序 | Sは仕様に合う必要がある |

## 3. 例1: 逐次一貫だがlinearizableでない履歴（H7）

```
q Enq(x) A
q Ok()   A      （履歴H7）
q Enq(y) B
q Ok()   B
q Deq()  B
q Ok(y)  B
```

実時間で見ると、Enq(x)が完了してからEnq(y)が始まっている。それなのにDeqがyを返しているので、FIFOに反して見える。これはlinearizableではない。

一方で、次のように並べ直せる。

```
q Enq(y) B
q Ok()   B
q Enq(x) A
q Ok()   A
q Deq()  B
q Ok(y)  B
```

- Aの操作はEnq(x)のみで、順序は保たれている
- BはEnq(y)の後にDeqで、元のまま
- yが先に入って先に出るので、FIFOに合っている

元の履歴と等価な正当な逐次履歴が存在するので、H7は逐次一貫である。L2を満たすSは存在しないので、linearizableではない。

| 見方 | H7の判定 |
|---|---|
| 実時間どおりに見たFIFO | 反している |
| 並べ直してよい（逐次一貫性） | OK |
| 実時間の順序も守る（linearizability） | NG |

「FIFOに反している」という直感はlinearizabilityの判定である。逐次一貫性は、プロセスをまたぐ実時間の前後関係を観測できないものとして扱う。

## 4. 局所的（local）でないとはどういうことか

性質Pが局所的であるとは、各オブジェクトがPを満たすなら、システム全体もPを満たすことをいう（3.1節）。linearizabilityは局所的だが、逐次一貫性はそうではない。

論文は、その反例として履歴H8を挙げている。

```
p Enq(x) A    q Enq(y) B
q Enq(x) A    p Enq(y) B
p Deq()→y A   q Deq()→x B
```

2つのキューpとq、2つのプロセスAとBがある。各プロセスの操作は上から下の順に実行される。

### オブジェクトごとに見ると逐次一貫

- pだけを見る: `B: Enq(y)` → `A: Enq(x)` → `A: Deq→y` と並べれば、キューの仕様に合う
- qだけを見る: `A: Enq(x)` → `B: Enq(y)` → `B: Deq→x` と並べれば、同じく合う

### 全体で見ると逐次一貫でない

(a)プロセス内の順序と(b)FIFOだけで、順序の制約が循環する。実時間の順序は使っていない。

1. p.Deq（A）がyを返す。(b)より、Sの中でyのEnqがxのEnqより前: `B: p.Enq(y)` → `A: p.Enq(x)`
2. Aの内部の順序 (a): `A: p.Enq(x)` → `A: q.Enq(x)`
3. q.Deq（B）がxを返す。(b)より: `A: q.Enq(x)` → `B: q.Enq(y)`
4. Bの内部の順序 (a): `B: q.Enq(y)` → `B: p.Enq(y)`

1〜4をつなぐと `B: p.Enq(y)` → … → `B: p.Enq(y)` と、自分自身より前に自分が来る循環になる。1列に並べられないので、H8は逐次一貫でない。

実時間の順序を無視してよいので並べ替えの自由度は大きいが、それでもこの履歴は並べられない。H8は「実時間を守れていないから」ではなく、「どう並べ替えても、プロセスの順序とFIFOを同時に満たせない」から逐次一貫でない。

## 5. 実務上の意味

局所的でない性質では、オブジェクトを個別に検証しても全体の正しさが保証されない。システム全体を一緒に見るか、オブジェクト間で追加の取り決めが必要になる。linearizabilityが局所的であることは、モジュール単位で検証できる根拠になる（論文3.1節）。
