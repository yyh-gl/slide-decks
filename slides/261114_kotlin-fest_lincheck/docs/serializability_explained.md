# 直列化可能性（Serializability）の解説

出典: M. Herlihy and J. Wing, "Linearizability: A Correctness Condition for Concurrent Objects", ACM TOPLAS, 1990, 3.3章（pp.473-474）。論文が明示していない比較は「4. 補足」に分けて書く。

## 1. 直列化可能性とは

**単位はトランザクション**である。トランザクションは、複数のオブジェクトに対する有限個の基本操作の列を、まとめて適用する制御スレッドである。linearizabilityや逐次一貫性が「1操作」を単位にするのとは、ここが違う。

- **直列化可能（serializable）**：トランザクション同士がインターリーブせず、1つずつ順番に実行されたように見える履歴と等価であること
- **厳密に直列化可能（strictly serializable）**：上に加えて、重ならないトランザクション同士の先行順序（実時間の前後関係）も、その順番で保たれていること

論文は、厳密な直列化可能性が2相ロックでは保証され、多版タイムスタンプ方式やネットワーク分断下で可用性を高める方式では保証されないと述べている。

また、直列化可能性はほぼ常に**失敗原子性**（実行を完了できないトランザクションを自動でロールバックする性質）とセットで提供される。linearizabilityには、これに当たるものがない。

## 2. linearizabilityとの関係と違い

linearizabilityは、「トランザクションが、単一オブジェクトへの単一操作だけからなる」場合の厳密な直列化可能性とみなせる。ただし論文は、この制約が実用上も形式上も大きな違いを生むと述べている。

| 観点 | 直列化可能性 | linearizability |
|---|---|---|
| 単位 | 複数オブジェクトにまたがるトランザクション | 単一オブジェクトへの単一操作 |
| 局所性 | なし（厳密な場合も） | あり |
| ブロッキング | 本質的にブロッキング | 全域的な操作はブロックしない |
| 並行制御 | 2相ロックなど。オブジェクト間で互換性が必要 | 専用の同期プロトコルで高い並行度を狙える |
| 適した領域 | データベース | マルチプロセッサOSなど |

直列化可能性向けの並行制御機構は、通常linearizabilityには不適切である。不要なオーバーヘッドと、並行性への不要な制約を持ち込むからである。論文は、第4章のキュー実装が、2相ロックや多版タイムスタンプによる同様の実装よりはるかに効率的で、並行度も高いと述べている。

### 2.1 局所的でない例（H8）

逐次一貫性の解説で使った履歴H8を、AとBをトランザクションとして読み直す。

```
A: p.Enq(x) → q.Enq(x) → p.Deq→y
B: q.Enq(y) → p.Enq(y) → q.Deq→x
```

- **オブジェクトごと**：H8|pとH8|qは、それぞれ厳密に直列化可能である。各オブジェクトでAとBは時間的に重なるので、先行順序の制約がなく、どちらの順番にも並べられる。
- **全体**：H8は、厳密どころか**直列化可能ですらない**。
  - Aを先に実行すると、AがDeqするyがまだEnqされていない。
  - Bを先に実行すると、BがDeqするxがまだEnqされていない。

このため、直列化可能なシステムでは、全オブジェクトの並行制御がグローバルな取り決めで互いに両立している必要がある。論文は、2相ロックと多版タイムスタンプが両立しない例を挙げている。

### 2.2 ブロッキングの例（H9）

```
x Read()  A → Ok(0)
y Read()  B → Ok(0)
x Write(1) B     （保留中）
y Write(1) A     （保留中）
```

Aはxを読んでからyに書き、Bはyを読んでからxに書こうとしている。2つの書き込みを両方完了させる直列化可能な順序は、存在しない。

- A→Bの順にすると、Bが読むyは1になるはずなのに、実際は0を読んでいる。
- B→Aの順にすると、Aが読むxは1になるはずなのに、実際は0を読んでいる。

どちらかをロールバックして再実行するしかない。論文は、このデッドロックが特定の機構の副産物ではなく、直列化可能性の概念そのものに内在すると述べている。一方、linearizabilityでは各書き込みを独立した操作として扱えるので、待たされない。

### 2.3 適した領域

- 直列化可能性：データベースのように、複数オブジェクトにまたがる複雑なアプリケーション固有の不変条件を、プログラマが容易に保てなければならないシステムに適する。2相ロックのような汎用の直列化プロトコルがあれば、トランザクションを逐次プログラムのように推論できる（デッドロックや性能の問題を除く）。
- linearizability：マルチプロセッサOSのように、並行性が主たる関心事であり、プログラマが専用の同期プロトコルを使い、並行性の影響を明示的に推論することをいとわないアプリケーションに向く。

## 3. 3つの条件の比較

| | 実時間の順序 | プロセス内の順序 | 単位 | 局所的 | ノンブロッキング |
|---|---|---|---|---|---|
| linearizability | 守る | 守る | 操作 | ○ | ○ |
| 逐次一貫性 | 守らない | 守る | 操作 | ×（H8） | 論文に記述なし |
| 直列化可能性 | 守らない | トランザクション内は守る | トランザクション | × | ×（本質的にブロッキング） |
| 厳密な直列化可能性 | 守る | トランザクション内は守る | トランザクション | × | ×（本質的にブロッキング） |

論文は、逐次一貫性のノンブロッキング性には触れていない。表の該当欄は、論文に記述がないという意味である。

## 4. 補足（論文にはない整理）

次の対応関係は、論文の記述ではなく解説者の整理である。

- 逐次一貫性とlinearizabilityの差は、「実時間の順序を守るか」である。直列化可能性と厳密な直列化可能性の差も、同じ「実時間の順序を守るか」である。
- つまり、「操作を単位にするか、トランザクションを単位にするか」と「実時間の順序を守るか」は、直交する2つの軸である。
  - 操作単位で実時間を守らない：逐次一貫性
  - 操作単位で実時間を守る：linearizability
  - トランザクション単位で実時間を守らない：直列化可能性
  - トランザクション単位で実時間を守る：厳密な直列化可能性
- ただし、逐次一貫性が「プロセスごとの順序」を守るのに対し、直列化可能性は「トランザクション内の操作の順序」を守る。この点は厳密には同じではないので、完全に対応するとは言えない。
